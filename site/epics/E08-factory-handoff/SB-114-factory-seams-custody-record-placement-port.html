SB-114: Factory seams: custody record, placement port, key hierarchy

Field Value
Epic E08 Factory and Hand-off
Wave / slice W1 / S1.2 Cell
Stories US-08.1
Manual sb-factory(7), sb-tenancy(7)
Laws LAW-18
Depends on SB-103, SB-105
Status Done

Why

Hand-off is planned for W7; these v1 seams make it a workflow later instead of a migration (ADR-0015).

Acceptance criteria

  • ✓Custody fields exist in the registry and in sb factory status output (v1 values only)
  • ✓A lint fails any code that reads an account id or key custodian from anywhere but the custody record
  • ✓sb tenant check rejects custody, placement and key_custodian in a manifest with a pointer to sb-factory(7)
  • ✓Design note in the devlog listing every seam and its test

Subtasks

  • ✓Update the man pages listed above first (manual first, P2)
  • ✓Add custody columns and reader API to the registry
  • ✓Define the Placement port with a factory-account adapter only
  • ✓Write the custody-field lint
  • ✓Manifest rejection messages and golden tests
  • ✓Read-only sb factory status
  • ✓Write or extend the law tests: LAW-18
  • ✓Devlog entry, ledger and changelog updated

Progress

2026-11-19: most seams arrived with SB-101 (manifest rejections), SB-103 (Placement and Keys ports, envelope keys) and SB-105 (custody columns and the CellByTenant reader). This ticket adds: - the custody constants, defined once in internal/core/cell/custody.go; - tools/check/custody.py (in make lint, with a self-test), which refuses account addresses, 12-digit ids and custody literals anywhere else; - read-only sb factory status TENANT, with a smoke test; - the first LAW-18 law test: every recorded cell names a key custodian, and its root key unwraps its data keys.

There was no red phase for the law test, because the code it tests already existed. Instead, its self-test shows that a missing custodian and a dead root key are both caught. The seams are listed in the devlog design note.

2026-11-19: reviewed by the user; CI green. Done.
