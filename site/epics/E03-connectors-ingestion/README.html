E03: Connectors and Ingestion

Sources flow in read-only through a four-call contract, with ACLs, provenance and freshness, and ingested text is treated as untrusted data.

Waves: W2, W6 · Tickets: 12 · Stories: 5

User stories

  • US-03.1: As a company IT operator, I want to connect docs and chat read-only from the manifest, so that setup is one line per source. Delivered by SB-201, SB-203, SB-204, SB-205.
  • US-03.2: As a company staff member, I want new and changed documents to show up within the freshness SLA, so that answers reflect today's truth. Delivered by SB-206, SB-208, SB-209.
  • US-03.3: As a security reviewer, I want ingested text treated as data, never as instructions, so that a poisoned document cannot drive an agent. Delivered by SB-207.
  • US-03.4: As a platform engineer, I want the index to be rebuildable from sources at any time, so that the index is never a system of record. Delivered by SB-210.
  • US-03.5: As a connector author, I want a contract kit and a fault-injecting mock, so that a new connector is correct by test, not by review. Delivered by SB-201, SB-202, SB-211, SB-610.
