SB-204: Chat connector (read-only)

Why

Decisions get made in chat; that knowledge should be findable by those who could see it.

Acceptance criteria

  • ✓Passes the contract kit
  • ✓Channel membership maps to ACL; private channels respected
  • ✓Direct messages are excluded by default

Subtasks

  • ✓Update the man pages listed above first (manual first, P2)
  • ✓Adapter
  • ✓Membership mapping
  • ✓DM exclusion test
  • ✓Contract kit run
  • ✓Write or extend the law tests: LAW-01
  • ✓Devlog entry, ledger and changelog updated

Progress

2026-11-19: the user chose Slack. internal/adapters/connectors/slack is read-only and standard library only, and it passes the contract kit against slacktest, a recorded fake of the Web API and the Events API's signed deliveries. - Each message is a document (thread replies included), and its version is the edit or post time in microseconds. - ACL: public channel means any full member (guests need membership); private channel means members only; no Slack account means Deny; a missing message or channel means Unknown. - DMs and group DMs are never read, and exclude patterns match channel names. - Changes come from verified Events API deliveries (v0 signature, 5-minute window) kept in an inbox. Joins and leaves become permission-only changes, and an empty cursor lists everything.

Tests: kit, membership mapping, exclusions, signature and staleness refusals, deletes. TestLAW03_SlackUnknownIsNeverAllow (with LAW-01's truth check) runs on it. While writing it, the law world twice mis-modelled faults (a 404 for one of two channels, then a leftover queued fault). The connector was right both times, and the world now injects one fault per channel in the batch.

Left: a real Slack workspace run (needs an app with the listed scopes, and a public URL for the Events API), and a durable inbox in the cell database.
