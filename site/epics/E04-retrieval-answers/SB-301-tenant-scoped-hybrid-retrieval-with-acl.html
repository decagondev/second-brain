SB-301: Tenant-scoped hybrid retrieval with ACL prefilter

Status Done

Why

Retrieval narrows candidates; it never grants access.

Acceptance criteria

  • ✓Vector plus keyword retrieval over the tenant's own index only
  • ✓Prefilter applied inside the query, not after
  • ✓LAW-02 green on real indexes

Subtasks

  • ✓Update the man pages listed above first (manual first, P2)
  • ✓Retriever port and pgvector adapter
  • ✓Keyword index
  • ✓Fusion ranking
  • ✓LAW-02 adversarial suite on real data
  • ✓Write or extend the law tests: LAW-02
  • ✓Devlog entry, ledger and changelog updated

Progress

2026-11-19 (slice S3.1, with SB-302 and SB-303): - ports.Retriever, and internal/adapters/postgres/index, the pgvector index. It has a schema per tenant (idx_TENANT), is bound to one tenant and refuses any other scope or chunk. Search uses cosine distance and tsvector keyword rank, each with acl && tokens in the WHERE clause, and is tested against real Postgres 17 with pgvector. - The in-memory index implements the same port for development and tests. - retrieve.Tokens builds the asker's prefilter tokens, and retrieve.Fuse does reciprocal-rank fusion (k = 60). - TestLAW02_NoTenantCrossing, red since W0, is green on the real pipeline. A self-test mutation (a cell that indexes another tenant's documents with a wrong prefilter) is caught. CI's postgres job now uses the pgvector/pgvector:pg17 image.
