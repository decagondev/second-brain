E40: An Agent for Every Department

Every department template has an agent worth asking, agents can run on a schedule or when something happens, and admins see every agent in one place.

Waves: W39 · Tickets: 7 · Stories: 2

Proposed 2026-11-24 after W37 and accepted by the user the same day, with every recommended decision. The concept is in 17-org-agents-os.md. Every ticket keeps to the bloat rules there: no new service the cell must run, no new store, no new third-party Go module, at most one setting a feature, no new page, nothing widens what anyone sees, a person approves every write, the tree only narrows, and agents are definitions in the release bundle.

User stories

  • US-40.1: As a person in any department, I want an agent for my department that answers with cites, so that my department's work gets faster answers. Delivered by SB-4001, SB-4002, SB-4003.
  • US-40.2: As an admin or steward, I want to see every agent, run one weekly, have a joiner and a transcript trigger one, and point askers to the right department, so that agents help without anyone remembering to ask. Delivered by SB-4004, SB-4005, SB-4006, SB-4007.

  • ✓Every new agent has an eval suite that passes the gate, and is refused outside its template's spaces

  • ✓A space with no active steward runs nothing

Decisions for the user

Decided 2026-11-24 (17-org-agents-os.md): all of W38 to W40, in order; a tree of at most three levels where a child is only stricter and members aren't inherited (SB-3901); agents stay definitions in the release bundle (SB-4001 to SB-4003); one weekly brief a space and two fixed triggers, drafts only and no tools (SB-4005, SB-4006); stewards see by name who hasn't read a policy (SB-4103); budgets warn at 80% and pause scheduled runs at 100% (SB-4105).
