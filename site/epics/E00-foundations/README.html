E00: Manual, Laws and Proofs

The spec, the laws and the first formal models exist before features, and CI enforces the process.

Waves: W0, W8 · Tickets: 22 · Stories: 7

User stories

  • US-00.1: As a maintainer, I want to read the man page for any feature before code exists, so that I know exactly what to build. Delivered by SB-004, SB-005, SB-006.
  • US-00.2: As a reviewer, I want CI to reject behaviour changes that do not change the manual, so that the manual never drifts from the code. Delivered by SB-007.
  • US-00.3: As a maintainer, I want the law tests to exist and fail red before features land, so that every feature is born against its laws. Delivered by SB-010.
  • US-00.4: As a security reviewer, I want the approval, rollout and permission designs model-checked, so that design flaws are found before code. Delivered by SB-011, SB-012, SB-013.
  • US-00.5: As a new contributor, I want one command that builds, tests and renders the docs, so that I am productive on day one. Delivered by SB-001, SB-002, SB-009, SB-016.
  • US-00.6: As a maintainer, I want read the space, policy and department pages before any space code exists, so that spaces are built to a spec, not invented in a pull request. Delivered by SB-801, SB-802, SB-803.
  • US-00.7: As a security reviewer, I want the space laws red and the spaces model checked before spaces exist, so that every space feature is born against its laws. Delivered by SB-804, SB-805, SB-806, SB-807.
